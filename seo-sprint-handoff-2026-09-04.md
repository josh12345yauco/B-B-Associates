## 5. Lead form — what actually happened (read this)

**Finding.** The contact page's live form was always GoHighLevel's iframe (form `k70Bwwhti09oNK8mRni7`). The inline code that POSTed to `links.legacylinqdigital.com/widget/form/Ey8fdi6O3JIdS1xYUhkw` was dead: that URL returns **404 Cannot POST**, and GHL's real `backend.leadconnectorhq.com/forms/submit` returns **429 "No tokens provided"** (needs a reCAPTCHA token only GHL's widget can mint). A native form cannot deliver into GHL, so the amendment as written could not be implemented literally.

**What shipped.** `js/inquiry-form.js` is the one shared module, mounted with `<div data-bb-inquiry data-source="…">` on the contact page, all 22 town pages and the 16 generated pages. Default mode renders GHL's own Contact Form iframe (same fields, same look, same delivery and email alerts as the contact page has today); `form_embed.js` relays the parent page URL to GHL for attribution, and the page context is appended as `?source_page=` for a hidden field if you add one in GHL. `native` mode (Supabase + localStorage + JSON POST to a GHL **Inbound Webhook**) is complete and tested locally except for the webhook itself; switch with `window.BB_INQUIRY_CONFIG = { mode:'native', ghlWebhook:'…' }`. `js/service-area-lead.js` is no longer referenced. The consultation form keeps its localStorage flow and additionally inserts into Supabase (webhook when configured).

**Tested locally.** Native mode: contact page submit → `localStorage.bb_leads` with correct `type/source/service_area`, `bb_conversion` dataLayer push fired, GHL POST attempted (404). Iframe mode: contact page, Ambler, and `/service-areas/kitchen-remodeling/bryn-mawr-pa/` all render the GHL form inside the page's form panel with no console errors. No test lead was pushed through the GHL iframe (it would email the client).
